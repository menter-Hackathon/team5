# 勝利条件・敗北条件（PL-06）

ゲームが終わる 4 つの結果と、その条件をパラメーターの値で決めます。

- 判定は `GameEndJudge`（CD-13）が行い、`GameManager.EndGame(GameResult, GameResultSummary)` を呼びます。
- 数値はすべて `GameBalance.asset` から読みます（parameters.md と同じ値。この文書で変えた値はありません）。
- 結果画面（CD-15）は `GameManager.LastResult` と `LastSummary` を見て、下の「結果画面の一言」を出します。

> **ステータス：案（メンバー確認待ち）**
> 数値の調整は PL-11（難易度・制限時間）で行います。条件の形（何がそろったら終わるか）はここで確定です。

---

## 1. 結果の一覧

| 結果 | `GameResult` | 条件（パラメーターの値で書く） | 結果画面の一言 |
|---|---|---|---|
| クリア | `Clear` | `RoleProgress ≥ roleProgressToWin`（= **100**） | 「{なりたいロール}になれた！ これが わたしらしさ。」 |
| 平和度0 | `GameOverPeace` | `Peace ≤ 0` | 「村にばれてしまった……『{押し付けロール}らしくない！』」 |
| 色が消えた | `GameOverFaded` | `Individuality ≤ 0` | 「色が消えてしまった。言われたとおりの{押し付けロール}になった。」 |
| 時間切れ | `GameOverTimeUp` | `GameTimer.Remaining ≤ 0`（`timeLimitSeconds` = **300** 秒）で、まだクリアしていない | 「時間切れ。{なりたいロール}には、まだなれなかった。」 |

- `{なりたいロール}` は `RoleDefinition.displayName`、`{押し付けロール}` は `RoleDefinition.imposedRoleName` を入れます。
- ramen_chef だと次のようになります。

| 結果 | 結果画面の一言（ramen_chef） |
|---|---|
| クリア | 「鶏白湯職人になれた！ これが わたしらしさ。」 |
| 平和度0 | 「村にばれてしまった……『勇者らしくない！』」 |
| 色が消えた | 「色が消えてしまった。言われたとおりの勇者になった。」 |
| 時間切れ | 「時間切れ。鶏白湯職人には、まだなれなかった。」 |

- パラメーターは `PlayerParameters.Add()` で 0〜最大値に丸められるので、`≤ 0` は実際には「ちょうど 0 になった」ときです。丸めを変えても判定がずれないよう、`== 0` ではなく `≤ 0` で書きます。

## 2. 決めたこと

### 2.1 個性を失いすぎたときの扱い → **今のまま（20 未満でデバフ、0 でゲームオーバー）**

| 個性の濃さ | どうなるか |
|---|---|
| 20 以上 | ふつう |
| 20 未満（`< debuffThreshold`） | 移動速度が 0.7 倍（`debuffSpeedMultiplier`）。HUD のゲージが点滅する（CD-14 への案） |
| 0 | すぐにゲームオーバー（`GameOverFaded`）。猶予なし |

理由：

- 会議の「場合によってはゲームオーバーにつながる」に、このままで合っています。20 未満になっても、それだけでは負けません。クラフト（+15〜+20）か初めての着替え（+10）で 20 以上に戻せば、デバフも外れます。
- 足が遅いと NPC の視界から逃げにくくなり、平和度でも負けやすくなります。「個性を失うと、逆らう力もなくなる」というテーマどおりの流れが、ルールを増やさずに作れます。
- 20 はお題 2 回分（-10×2）で 0 になる位置なので、「あと 2 回言いなりになったら消える」という警告として分かりやすいです（parameters.md）。
- 0 になったときに猶予（数秒待つ、など）を入れる案は採りません。個性が下がるのは「お題を完了したとき」だけで、プレイヤーが自分で選んだ行動の結果だからです。猶予を入れると、そのあいだに何をすれば助かるのかの説明が増えます。
- 境目：ちょうど 20 はデバフなし、ちょうど 0 は負けです。

### 2.2 「そのロールのタスクを全部こなしたらクリア」→ **進み具合 100 と同じ意味にする（条件は 1 つだけ）**

クリアの条件は `RoleProgress ≥ 100` の 1 つだけにし、「最終アイテムを持っている」「裏の行動を全部した」は別の条件として判定しません。

理由：

- 進み具合が上がるのはクラフトだけで、ramen_chef のレシピ 3 つ（30＋30＋40）を全部作るとちょうど 100 です（items.md・parameters.md）。素材は「ちょうど足りる数」しか置かないので、同じレシピを何回も作って稼ぐこともできません。
- `paitan` は `soup_base` と `noodle` が材料なので、必ず最後に作ることになります。つまり **進み具合 100 ＝ 裏のクラフトを全部した ＝ `paitan` を作った** で、3 つは同じ瞬間に起きます。
- 同じことを別々の条件で判定すると、数値を調整したとき（PL-11）にどちらかだけずれて「100 なのにクリアにならない」が起きやすくなります。判定を 1 つにしておけば、そうしたバグが入りません。
- 着替えは個性だけが上がり、進み具合は上がらないので、クリアには必要ありません（衣装は寄り道でも、個性を守る手段として使えます）。
- 「タスク」が **表のお題** のことなら、全部こなすとクリアにはしません。お題は個性を下げるので、それでクリアになるとテーマ（押し付けられた「らしさ」に逆らう）と逆になるためです。

この決め方を守るために、ロールを追加するとき（M2）は次のルールでレシピを作ります。

- そのロールのレシピの `roleProgressReward` の合計を **ちょうど 100** にする。
- `goalItem` を作るレシピは、ほかのレシピでできたものを材料にして、必ず最後になるようにする。
- 素材は「ちょうど足りる数」だけ置く。

## 3. 判定のしかた（CD-13 向け）

`GameEndJudge` は次のイベントを購読します。

| イベント | 見るもの | 結果 |
|---|---|---|
| `PlayerParameters.OnChanged(RoleProgress, 前, 後)` | `後 ≥ roleProgressToWin` | `Clear` |
| `PlayerParameters.OnChanged(Peace, 前, 後)` | `後 ≤ 0` | `GameOverPeace` |
| `PlayerParameters.OnChanged(Individuality, 前, 後)` | `後 ≤ 0` | `GameOverFaded` |
| `GameTimer.OnTimeUp` | （クリアしていなければ） | `GameOverTimeUp` |

- **一度終わったら判定しない**：`GameManager.State` が `Playing` でなければ何もしません。最初に条件を満たしたものが結果になります。
- **同じフレームで 2 つ以上そろったとき**は、`Clear` → `GameOverPeace` → `GameOverFaded` → `GameOverTimeUp` の順で先にあるほうを採ります（プレイヤーに有利なほうを優先）。今の数値では、1 回の行動で 2 つの条件が同時にそろうことはありません（お題の完了は個性 -10 と平和度 +10、失敗と見つかるのは平和度だけ、クラフトはどちらも上がる）。タイマーと重なったときのための決まりです。
- **クラフト中に時間切れ**になったら、そのクラフトは完成しません（`GameOverTimeUp`）。最後の 1 秒で `paitan` が完成するのは、完成のほうが先なら `Clear` です。
- **一時停止中**（`Paused`）はタイマーが止まり、パラメーターも変わらないので判定もしません。
- **デバフ**（2.1 の表）も CD-13 で入れます。`Individuality < debuffThreshold` のあいだ、プレイヤーの移動速度に `debuffSpeedMultiplier` を掛けます。`OnChanged(Individuality, …)` で切り替えれば毎フレーム調べる必要はありません。

`EndGame` に渡す `GameResultSummary` は、終わった瞬間の値をそのまま入れます。

| フィールド | 入れる値 |
|---|---|
| `individuality` | `PlayerParameters.Get(Individuality)` |
| `peace` | `PlayerParameters.Get(Peace)` |
| `roleProgress` | `PlayerParameters.Get(RoleProgress)` |
| `elapsedSeconds` | `GameTimer.Elapsed` |
| `tasksCompleted` | 完了した表のお題の数（`TaskManager`） |
| `timesCaught` | 見つかった回数（`SurveillanceManager`） |

## 4. 結果画面（CD-15 向け）

一言の下に、負けた理由が分かるヒントを 1 行出します（次に遊ぶときの手がかり）。

| 結果 | ヒント（1 行） | 見せたい数値 |
|---|---|---|
| クリア | 「言われたこともこなしつつ、自分の『好き』を守れた！」 | かかった時間、こなしたお題の数、見つかった回数 |
| 平和度0 | 「らしくない行動は、だれも見ていないときに。お題をこなすと平和度が戻るよ」 | 見つかった回数、進み具合 |
| 色が消えた | 「お題ばかりだと色が消えちゃう。こっそりクラフトして個性を取り戻そう」 | こなしたお題の数、進み具合 |
| 時間切れ | 「素材を先に集めておくと、クラフトが早く終わるよ」 | 進み具合 |

- 背景や色は DS-08 のデザインに合わせます。クリアはロールの色（`roleColor`）、色が消えたは灰色、などの案を DS-08 に渡します。
- 結果画面の一言は仮のセリフです。言い回しは自由に直して構いません（`GameResult` との対応だけは変えない）。

## 5. 確認：4 つの結果がすべて起きるか（ramen_chef）

parameters.md の「5 分でどうなるか」と同じ数値です。

| 遊び方 | どうなるか | 結果 |
|---|---|---|
| 素材を集めて 3 つ全部作る | 進み具合 30 → 60 → **100** | `Clear` |
| お題だけこなす | 個性 50 → 5 回目で **0** | `GameOverFaded` |
| お題を無視し、1 回見つかる | 平和度 70 → 失敗 3 回 + 見つかる 1 回で **0** | `GameOverPeace` |
| お題も平和度も保てたが、`paitan` が間に合わない | 残り時間 **0**、進み具合 60 など | `GameOverTimeUp` |

- 4 つとも起きます。どれか 1 つだけを狙っても勝てない（お題だけ → 消える、無視だけ → ばれる、遅い → 時間切れ）ので、条件はこのまま確定します。
