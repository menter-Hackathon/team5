# パラメーターと数値（PL-04）

ゲーム中に増減する数値（パラメーター）と、その初期値・増減量をまとめます。

- **GameBalance** の表は、そのまま `Assets/_Project/Data/GameBalance.asset` のインスペクターに入れる値です。
- お題・レシピ・衣装ごとの数値は、それぞれ `TaskDefinition` / `RecipeDefinition` / `OutfitDefinition` のフィールドに入れます（下の「3. 行動ごとの増減」）。
- 数字はコードに直接書かず、すべてアセットから読みます（architecture.md 5 章）。

> **ステータス：案（メンバー確認待ち）**
> 一度遊んでから PL-11（難易度・制限時間）で調整します。勝ち負けの条件そのものは PL-06（win-lose.md）で決めます。

---

## 1. パラメーターの一覧


| パラメーター | コード上の名前（`ParameterType`） | 範囲 | 初期値 | 上がる | 下がる | 0 / 最大になると |
|---|---|---|---|---|---|---|
| 個性の濃さ | `Individuality` | 0〜100 | 50 | クラフト、初めての着替え | 表のお題を完了する | 0 で負け（色が消える）。20 未満で足が遅くなる |
| 村の平和度 | `Peace` | 0〜100 | 70 | 表のお題を完了する | お題に失敗する、らしくない行動を見られる | 0 で負け（村にばれる） |
| ロールへの進み具合 | `RoleProgress` | 0〜100 | 0 | クラフト | 下がらない | 100 で勝ち（なりたいロールになれた） |

- 3 つとも `PlayerParameters.Add()` で 0〜最大値に丸めます（最大値を超えた分は捨てる）。
- 時間がたつだけで自然に増えたり減ったりはしません。増減はすべてプレイヤーの行動がきっかけです（何をしたら色が変わったのかが分かりやすいように）。
- **進み具合が上がるのはクラフトだけ**です（items.md と同じ。着替えは個性だけが上がる）。

## 2. GameBalance の値

| 項目 | 仮の値 | 決定値 | 理由 |
|---|---|---|---|
| `timeLimitSeconds` | 300 | **300** | ramen_chef の最短ルート（素材 5 か所＋クラフト 11 秒）に、お題をこなしながら 3〜4 分かかる見込み。発表のデモにも 5 分なら収まる |
| `individualityInitial` | 50 | **50** | 真ん中から始めると、お題で薄くなるのも、クラフトで濃くなるのも最初から見た目で分かる（CD-07 で 0.5＝半分色がついた状態） |
| `individualityMax` | 100 | **100** | 割合（%）として読めるように |
| `debuffThreshold` | 20 | **20** | お題 2 回分（10×2）で 0 になる位置。「あと 2 回言いなりになったら消える」という警告のライン |
| `debuffSpeedMultiplier` | 0.6 | **0.7** | 0.6 だと NPC の視界から逃げられず、そのまま負けが決まりやすい。遅いのは分かるが、まだ立て直せる速さにする |
| `peaceInitial` | 100 | **70** | 100 から始めると、最初のうちはお題を完了しても平和度が増えず意味がない。70 なら「お題をこなす＝村に受け入れられる」が最初から効く。また、何もしなければ **3 回見つかるとアウト**（70→45→20→-5）と分かりやすい |
| `peaceMax` | 100 | **100** | 割合（%）として読めるように |
| `caughtPeacePenalty` | 25 | **25** | 上のとおり「3 回でアウト」。お題を 3 回こなせば（+30）、見つかる 1 回分以上を取り返せる |
| `caughtCooldownSeconds` | 2 | **3** | 見つかったあと、びくっとするアニメ（AN-01 の `Caught`）の間に連続で減らないように。3 秒あれば視界の外に逃げられる |
| `roleProgressMax` | 100 | **100** | 割合（%）として読めるように |
| `roleProgressToWin` | 100 | **100** | ramen_chef のレシピ 3 つ（30＋30＋40）でちょうど 100（items.md）。最後の `paitan` を作った瞬間にクリア |
| `taskIntervalSeconds` | 20 | **20** | お題をすぐこなすと 1 回およそ 35 秒（間隔 20＋移動と作業 15）。5 分で 8 回ほど出て、全部こなすと個性 -80。裏の行動（最大 +70）とちょうど張り合う量 |

## 3. 行動ごとの増減

数値はどのアセットのどのフィールドに入れるかも書いています。空欄（-）は変わらないという意味です。

| 行動 | 個性の濃さ | 村の平和度 | 進み具合 | どこに入れるか |
|---|---|---|---|---|
| 表のお題を完了する | **-10** | **+10** | - | `TaskDefinition.individualityCost` / `peaceReward` |
| 表のお題に失敗する（制限時間切れ） | - | **-15** | - | `TaskDefinition.failPeacePenalty` |
| クラフト：`soup`（鶏ガラスープ） | **+15** | - | **+30** | `RecipeDefinition.individualityReward` / `roleProgressReward` |
| クラフト：`noodle`（手打ち麺） | **+15** | - | **+30** | 同上 |
| クラフト：`paitan`（鶏白湯ラーメン） | **+20** | - | **+40** | 同上 |
| 着替える：`chef_apron`（初めて） | **+10** | - | - | `OutfitDefinition.individualityReward` |
| 着替える：`chef_towel`（初めて） | **+10** | - | - | 同上 |
| 同じ服をもう一度着る | - | - | - | （初めてのときだけ増える） |
| らしくない行動を見られる | - | **-25** | - | `GameBalance.caughtPeacePenalty`（3 秒に 1 回まで） |
| クラフト中に見つかって中断 | - | **-25**（見つかった分） | - | 材料は減らず、もう一度作り直せる（CD 側の案） |
| 素材を拾う | - | - | - | 拾うだけなら何も変わらない（見られていれば「らしくない行動」） |

- ramen_chef の 4 つのお題（`swing` `eat_ramen` `bring_wood` `report_guard`）はすべて同じ値（-10 / +10 / -15）にします。お題によって差をつけるのは、遊んでみてから（PL-11）。
- 失敗のほうが完了より平和度が大きく動く（-15 と +10）のは、「無視すれば済む」にならないようにするためです。
- 衣装の段階（1 / 2）と見た目は PL-07（outfits.md）で決めます。ここで決めるのは個性の数値だけです。

### 確認：5 分でどうなるか（ramen_chef）

お題は 4 つを順番に出し、最後まで行ったら最初に戻る想定です（CD-09 で決まったら合わせる）。

| 遊び方 | 個性の濃さ | 村の平和度 | 結果 |
|---|---|---|---|
| **言いなり**：お題だけこなす | 50 → 4 回目で 10（足が遅くなる）→ 5 回目（3 分ごろ）で **0** | 70 → 100 | 負け（色が消える） |
| **全部無視**：お題をやらず、見つからない | 50 のまま（クラフトすれば増える） | 失敗 5 回（約 280 秒）で 70 → **-5** | クラフトが間に合えば勝ち、遅ければ負け |
| **全部無視**して 1 回見つかる | 50 | 失敗 3 回（約 170 秒）＋見つかる 1 回で **0** | 負け（村にばれる） |
| **バランス**：8 回のお題のうち 6 回こなし 2 回失敗、全部作って両方着る、1 回見つかる | 50 - 60 + 50 + 20 = **60** | 70 + 60 - 15×2 - 25 = **75** | 勝ち |

- 「言われたことばかりだと消える」「逆らいすぎるとばれる」の両方が起き、どちらかに寄せるだけでは勝てない数値にしています。
- `paitan` を作った時点で進み具合が 100 になり、そのときに勝ちが決まります。

## 4. 個性の濃さと見た目

CD-07 のシェーダーは `_Individuality`（0〜1）で動きます。値は `個性の濃さ ÷ individualityMax`（`PlayerParameters.GetNormalized`）です。間の値はなめらかにつなぎ、変わるときは 0.5 秒かけて変化します（CD-07）。

| 個性の濃さ | `_Individuality` | 彩度 | 不透明度 | 輪郭の太さ | 色 | どう見えるか |
|---|---|---|---|---|---|---|
| **0** | 0 | 0（灰色） | 0.25 | 0（なし） | ベース色 | 灰色で透けた霧のよう。村の背景に溶けて見えない「無個性なモブ」。ここで負け |
| 20（デバフのライン） | 0.2 | 0.2 | 約 0.43 | 約 0.004 | ベース色 | ほぼ灰色で、向こうが透けて見える。輪郭はうっすら。足が遅くなる |
| **50**（スタート） | 0.5 | 0.5 | 0.7 | 0.01 | ベース色 | くすんだ色がついて、少し透けている。輪郭が見える |
| **100** | 1 | 1 | 1（透けない） | 0.02 | ベース色にロールの色を 30% 混ぜる | はっきりした色と太い輪郭。ramen_chef ならロールの色（roles.md の `roleColor`）が混ざる |

- CD-07 の表とずれはありません。20 の行は、0 と 50 の間を直線でつないだときの目安です。
- 個性の濃さ（色・輪郭）と衣装の段階（服の形）は別のものです。衣装は着替えで変わり、色の濃さは個性の数値で変わります。
- 足が遅くなっていることが見た目でも分かるよう、20 未満では HUD のゲージを点滅させる案を CD 側（HUD）に渡します。

## GameBalance.asset への反映

`GameBalance.asset` はまだリポジトリにないため、作るときのデフォルト値になる architecture.md の `GameBalance`（と `TaskDefinition.failPeacePenalty`）を上の決定値に直しました。アセットを作ったあとは、インスペクターの値が上の表と同じか確認してください。

変えたのは次の 4 つです（ほかは仮の値のまま決定）。

| クラス | 項目 | 仮の値 → 決定値 |
|---|---|---|
| `GameBalance` | `debuffSpeedMultiplier` | 0.6 → 0.7 |
| `GameBalance` | `peaceInitial` | 100 → 70 |
| `GameBalance` | `caughtCooldownSeconds` | 2 → 3 |
| `TaskDefinition` | `failPeacePenalty` | 10 → 15 |
